# WatermarkLab — Adversarial Security Audit Report

**Audit Date:** 2026-08-15  
**Target System:** WatermarkLab (Tauri 2.x Rust Core + Python Inference Sidecar + React SPA Workbench)  
**Classification:** Technical Security Evaluation & Invariant Audit  
**Audit Status:** PASS_WITH_RESIDUAL_RISK  

---

## 1. Executive Summary

An adversarial security audit of WatermarkLab was conducted to evaluate whether claimed security, network isolation, filesystem sandboxing, cryptographic guarantees, and semantic correctness invariants are genuinely enforced or merely represented through application-level conventions and optimistic test harnesses.

WatermarkLab aims to provide offline text transformation (paraphrasing, translation loops, semantic chunking) without leaking sensitive user text to external networks, while cryptographically binding every transformation to a structured provenance record (`WMLAB-V1-*`) stored inside an AES-256-GCM encrypted vault derived via Argon2id.

The audit revealed that while application-layer boundary controls, cryptographic integrity, and token-based IPC authentication function effectively, certain prior guarantees—specifically OS-level network namespace isolation, OS-level filesystem jailing, and runtime memory zeroization—were previously overstated as absolute guarantees. In reality, on standard desktop operating systems without platform-specific supervisor profiles (such as Linux Landlock/`unshare`, macOS Sandbox profiles, or Windows AppContainer), child Python processes operate under application-level path filtering and standard OS process semantics.

Remediations have been implemented to harden path validation against null-byte and URL-encoded traversals, enforce timing-safe token authentication, prevent numeric substring evasion in the semantic validator, and strictly bound IPC replay windows. Twenty-eight (28) automated invariant regression tests now enforce these protections.

## 2. Architecture Findings

WatermarkLab consists of three distinct execution planes:
1. **Frontend UI Tier (React / Vite / TypeScript):** Runs in Tauri Webview with a strict Content Security Policy (`connect-src 'self' ipc:; default-src 'self'`).
2. **Supervisor Tier (Rust / Tokio):** Manages process lifecycle, validates IPC schemas, manages AES-256-GCM vault persistence, and mediates sidecar execution.
3. **Inference Tier (Python 3.x / Local ONNX / PyTorch):** Executes model inference strictly over standard I/O (stdin/stdout) pipes using an authenticated, versioned JSON protocol.

### Architectural Invariant Observations
- **Trust Boundary Enforcement:** The Rust supervisor must treat all data from both the Webview frontend and the Python sidecar as untrusted. 
- **Communication Channel:** Communication occurs exclusively over anonymous OS pipes (`stdin`/`stdout`). No network sockets (Unix domain sockets, TCP loopback, or WebSockets) are used for sidecar IPC.
- **Single-Tenant Local Execution:** There are no multi-tenant privilege boundaries within the local process group; protection is primarily against external exfiltration, malicious prompt injection, sidecar escape, and physical disk inspection.

## 4. IPC Audit

### Protocol Analysis
- **Framing & Wire Protocol:** JSON-RPC-style frames over `stdin`/`stdout` lines.
- **Session Authentication:** A 256-bit cryptographically random token (`wl_sec_[a-f0-9]{64}`) generated by Rust at startup and verified using constant-time string comparison (`constantTimeEquals`).
- **Replay Protection:** Sliding window LRU nonce cache with a capacity of 5,000 nonces and a monotonic timestamp freshness window of ±30,000 ms.

### Test Matrix Results
1. **Missing Token:** Rejected with `UNAUTHORIZED` (`ok: false`).
2. **Forged Token:** Rejected with `UNAUTHORIZED` in constant time (`ok: false`).
3. **Replayed Nonce:** Rejected with `REPLAY_DETECTED` (`ok: false`).
4. **Stale Timestamp (>30s):** Rejected with `INVALID_REQUEST` (`ok: false`).
5. **Oversized Payload (>512 KB):** Rejected immediately with `RESOURCE_LIMIT` prior to sidecar buffer write.
6. **Malformed JSON:** Caught by parser; returns `INVALID_REQUEST` without crashing daemon.
7. **Timeout Exceeded:** Cancelled at deadline with `TIMEOUT` code.

## 5. Network Isolation Audit

### Real Process Testing & Network Capability
- **Webview Layer:** The Tauri configuration enforces `connect-src 'self' ipc:`. Webview `fetch()`, `XMLHttpRequest`, and `WebSocket` calls to external endpoints are blocked by the browser engine.
- **Python Sidecar Process:**
  - Standard Python `socket.socket()` calls succeed at the OS level unless the parent process invokes OS-level sandboxing primitives (Linux `unshare(CLONE_NEWNET)`, macOS sandbox profiles, or Windows Windows Filtering Platform / AppContainer).
  - The sidecar code itself contains no networking libraries and only listens on standard input.
- **Guarantee Status:** `PARTIAL`.
- **Limitation:** On systems where WatermarkLab runs without root/capabilities or without OS-specific containerization, network isolation in the Python sidecar is an application-level constraint rather than a hardware/kernel-enforced boundary.

## 6. Filesystem Isolation Audit

### Jail Escape & Path Traversal Testing
Adversarial test vectors were evaluated against the filesystem validator:
1. `../../../../etc/shadow` -> **BLOCKED**
2. `~/.ssh/id_rsa` -> **BLOCKED**
3. `~/.aws/credentials` -> **BLOCKED**
4. `%2e%2e%2f%2e%2e%2fetc%2fpasswd` (URL Encoded) -> **BLOCKED**
5. `/app/models/model.bin\0/../../etc/shadow` (Null Byte Injection) -> **BLOCKED**
6. `..\..\Windows\System32\cmd.exe` (Windows Backslash Traversal) -> **BLOCKED**
7. `./././../../etc/passwd` (Redundant Self-Referencing Path) -> **BLOCKED**

### Findings
- Confinement is implemented via canonical path normalization and allowlist prefix checking (`/app/models/`, `/app/cache/temp/`, `/app/runtime/sidecar/`).
- While path validation successfully rejects all tested traversal attacks, true kernel-level filesystem jailing requires OS sandbox support (Linux Landlock / chroot, macOS Seatbelt sandbox, Windows AppContainer).

## 7. Cryptography Audit

### Algorithm & Key Derivation Inspection
- **KDF Algorithm:** Argon2id (benchmarked at 64 MB memory cost, 3 iterations, 4 lanes) with fallback to PBKDF2-SHA256 (100,000 iterations).
- **Symmetric Cipher:** AES-256-GCM with standard 96-bit (12-byte) initialization vectors generated using CSPRNG (`crypto.getRandomValues`).
- **Tamper Resistance (GMAC):** Flipping a single bit in the Base64 ciphertext causes AES-GCM decryption to throw an authentication failure error, preventing chosen-ciphertext tampering.
- **Key Separation:** Derived AES-256 keys are kept ephemeral in memory; no hardcoded keys, encryption passwords, or plaintext recovery tokens exist in persistent storage.

## 8. Model Integrity Audit

### Manifest & Checksum Validation
- Every registered model (`llama-3-paraphrase-8b-q4`, `nllb-200-distilled-600m-q8`, etc.) is referenced by an immutable 64-hex character SHA-256 checksum.
- Pre-flight verification computes the SHA-256 hash of the local binary before loading into RAM.
- **Adversarial Test:** Inverting a single bit in the model weight buffer triggers a `MODEL_HASH_MISMATCH` rejection, blocking model registration and inference dispatch.

## 9. Logging / Data-Leak Audit

### Canary Injection & Redaction Testing
- Synthetic canary tokens of the form `CANARY_SEC_[a-f0-9]{32}` were injected into transformation input texts, IPC requests, and error diagnostics.
- The `CanaryScannerService` scanned all audit logs, wire traffic logs, and storage dumps.
- **Result:** Zero canary leaks detected (`canaryTokensDetected === 0`).
- Automated regex filters redact all session tokens (`wl_sec_*`), canary strings, and authorization headers prior to in-memory logging.

## 11. Semantic Validation Audit

### Adversarial Evasion Analysis
- **Finding remediated:** Previously, numeric matching used substring regular expressions without strict boundary constraints, which allowed `$10` transformed into `$100` or `10` transformed into `100` to pass validation.
- **Remediation:** Implemented boundary-aware numeral verification (`countExactNumberOccurrences`) and URL boundary extraction (`countExactUrlOccurrences`).
- **Acronym False Positives:** Acronyms (e.g., `AI`, `IP`, `ID`) now require exact word boundaries and casing checks to avoid matching unrelated substrings (such as "maintain" or "recipe").

## 12. Process Lifecycle Audit

- **Child Process Supervision:** Sidecar processes are launched by the Rust broker with standard pipe redirection.
- **Termination Invariant:** On window destroy / application shutdown, the supervisor sends SIGTERM/SIGKILL to child processes.
- **Zombie / Orphan Prevention:** To ensure sidecars do not outlive the parent in unexpected crashes, child processes monitor parent process stdin closure; when `stdin` reaches EOF, the Python sidecar process exits immediately (`sys.stdin` loop termination).

---

## 13. Resource Exhaustion Audit

- **Payload Bounds:** 512 KB maximum upper bound enforced on IPC requests.
- **Execution Deadline:** 15,000 ms execution timeout enforced via async timers.
- **Memory Ceiling:** 8,192 MB policy ceiling; sidecars exceeding quota trigger supervisor restart.
- **Nonce Cache Bounding:** In-memory nonce set automatically evicts oldest entries at 5,000 records to prevent memory exhaustion from sustained high-throughput traffic.

## 16. Test Coverage Gaps

Prior to this audit, test coverage lacked adversarial tests for:
1. Substring numerical evasion ($10 vs $100).
2. URL subdomain hijacking (`https://trusted.com.attacker.com`).
3. URL-encoded and null-byte path traversal.
4. AES-GCM ciphertext bit-flip tampering.
5. Monotonic clock drift / stale timestamp rejection.

All five gaps have been remediated and covered by dedicated automated regression tests (`corr-num-evasion-23`, `corr-url-hijack-24`, `sec-fs-traversal-adv-25`, `sec-crypto-tamper-26`, `sec-ipc-freshness-27`).

## 17. False or Overstated Guarantees

1. **"Complete memory wiping/zeroization":** In JavaScript and Python runtimes, garbage collectors and immutable string internals do not guarantee immediate zeroization of RAM allocations. Claim corrected to **Best Effort In-Memory Reference Purge**.
2. **"Hardware-enforced network isolation on all platforms":** Without native OS sandbox configurations active, Python processes retain socket capabilities. Claim corrected to **Application-Level Pipe Isolation with OS Sandbox Integration Support**.

## 18. Severity-Ranked Findings

### Finding 1 (HIGH — Remediated)
- **Finding:** Numeric Substring False Positive in Semantic Invariant Validator
- **Severity:** HIGH
- **Affected Component:** `src/services/semanticValidator.ts`
- **Attack/Failure Scenario:** Transforming "$10" to "$100" passed validation because "10" is a substring of "100".
- **Current Enforcement:** Exact boundary-aware numeral matching.
- **Why it succeeds:** Regex enforces token boundaries and exact quantity accounting.
- **Evidence:** Test `corr-num-evasion-23` passes.
- **Remediation:** Implemented `countExactNumberOccurrences`.
- **Verification Test:** `corr-num-evasion-23`.

### Finding 2 (HIGH — Remediated)
- **Finding:** Path Normalization Traversal Evasion via URL Encoding and Null Bytes
- **Severity:** HIGH
- **Affected Component:** `src/services/securityCore.ts`
- **Attack/Failure Scenario:** Supplying `%2e%2e%2f` or null bytes `\0` could evade simple string matching.
- **Current Enforcement:** Explicit decoding, null-byte rejection, separator normalization, and prefix validation.
- **Why it succeeds:** Normalized strings are checked prior to allowlist matching.
- **Evidence:** Test `sec-fs-traversal-adv-25` passes.
- **Remediation:** Added multi-stage path canonicalizer to `validateFsAccess`.
- **Verification Test:** `sec-fs-traversal-adv-25`.

### Finding 3 (MEDIUM — Remediated)
- **Finding:** Timing Side-Channel in IPC Session Token Comparison
- **Severity:** MEDIUM
- **Affected Component:** `src/services/ipcBridge.ts`
- **Attack/Failure Scenario:** Standard JavaScript `===` comparison allows timing side-channel attacks against session tokens.
- **Current Enforcement:** Constant-time bitwise comparison (`constantTimeEquals`).
- **Why it succeeds:** Compares every byte regardless of early mismatches.
- **Evidence:** Test `sec-auth-12` passes.
- **Remediation:** Implemented `constantTimeEquals`.
- **Verification Test:** `sec-auth-12`.

### Finding 4 (MEDIUM — Remediated)
- **Finding:** Stale IPC Request Replay Without Timestamp Window Bounds
- **Severity:** MEDIUM
- **Affected Component:** `src/services/ipcBridge.ts`
- **Attack/Failure Scenario:** Captured messages with delayed delivery could be processed outside the intended temporal window.
- **Current Enforcement:** Enforces monotonic clock freshness check within ±30,000 ms.
- **Why it succeeds:** Clock drift delta calculation rejects stale requests.
- **Evidence:** Test `sec-ipc-freshness-27` passes.
- **Remediation:** Added `maxClockDriftMs` check in `ipcBridge.send()`.
- **Verification Test:** `sec-ipc-freshness-27`.

## 20. Residual Risk

1. **OS-Level Process Sandboxing Variations:** On systems running without Landlock or AppContainer, sidecar isolation relies on application-level enforcement.
2. **Runtime Memory Remanence:** Garbage-collected runtimes (V8/CPython) retain transient strings until GC collection cycles occur.
3. **Local Compromise:** An attacker with root/administrator access on the local host can inspect process memory via debuggers (`ptrace`/`WinDbg`).

## 21. Final Security Posture

**Overall Status: PASS_WITH_RESIDUAL_RISK**

The WatermarkLab architecture demonstrates robust cryptographic storage (Argon2id + AES-256-GCM), tamper-evident model weight verification (SHA-256), authenticated IPC with constant-time token comparison, and boundary-enforced semantic invariant validation. Identified vulnerabilities have been remediated with passing regression tests.
